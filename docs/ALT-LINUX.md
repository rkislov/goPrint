# GoPrint на ALT Linux 10 и 11

Выпуск v0.2.0-beta.5, 4 ноября 2026 г. Автор: Кислов Роман Сергеевич. Apache-2.0.

## Выбор пакета

Пакеты p10 предназначены для ALT Linux 10, p11 — для ALT Linux 11. Архитектура x86_64 соответствует Linux amd64, aarch64 — arm64. Узнайте систему командами `cat /etc/altlinux-release` и `uname -m`. Не смешивайте ветки. Это пакеты проекта GoPrint, а не пакеты официального репозитория ALT.

В [релизе](https://github.com/rkislov/goPrint/releases/tag/v0.2.0-beta.5) скачайте SHA256SUMS и один RPM:

- goprint-0.2.0-alt0.beta.5.p10.1.x86_64.rpm
- goprint-0.2.0-alt0.beta.5.p10.1.aarch64.rpm
- goprint-0.2.0-alt0.beta.5.p11.1.x86_64.rpm
- goprint-0.2.0-alt0.beta.5.p11.1.aarch64.rpm

RPM не подписаны GPG. Проверяйте SHA-256 по файлу из того же доверенного релиза; контрольная сумма не заменяет подпись издателя.

## Установка

Пример для ALT 11 x86_64. Выполните от root, находясь в каталоге загрузки:

```sh
sha256sum --ignore-missing -c SHA256SUMS
apt-get update
apt-get install ./goprint-0.2.0-alt0.beta.5.p11.1.x86_64.rpm
goprint-setup
```

Убедитесь, что проверен именно выбранный RPM. apt-get установит зависимости CUPS, cups-filters и Ghostscript из настроенных репозиториев вашей ветки. Сервис не запускается автоматически. goprint-setup создаёт случайный административный токен в /etc/goprint/environment, не выводит его в журнал и при повторном запуске сохраняет существующий токен. Прочитайте файл от root для первого входа и храните токен как пароль администратора.

```sh
systemctl enable --now goprint
systemctl status goprint --no-pager
goprintd -version
journalctl -u goprint -n 50 --no-pager
```

По умолчанию интерфейс доступен только на http://127.0.0.1:8631. Для удалённой первичной настройки используйте SSH-туннель либо настройте HTTPS reverse proxy и public-url по инструкции администратора. Не публикуйте токен и файл environment. Перед изменением сетевых параметров изучите `goprintd -help` и штатный unit; переопределения службы создавайте через `systemctl edit goprint`, а не редактированием файла пакета.

## Файлы и права

Шесть утилит устанавливаются в /usr/bin, goprint-setup — в /usr/sbin. Служба работает от системного пользователя goprint. Конфигурация /etc/goprint/environment имеет права root:goprint 0640, каталог /etc/goprint — 0750. Данные очередей, сканов и ключей находятся в /var/lib/goprint, доступном только пользователю службы (0700). Инструкции, лицензии, примеры и сведения о сборке: /usr/share/doc/goprint.

PPD производителей скачиваются отдельно при обновлении каталога и сохраняют собственные лицензии. Исполняемые драйверы производителя не входят в RPM. Для Sindoh N410/N610 необходим отдельный фирменный фильтр; см. SINDOH.md. SMB требует отдельно установленного smbclient; другие дополнительные службы также включаются только по необходимости.

## Проверка после установки

Войдите администратором, проверьте раздел фильтров: cupsfilter и pdftops должны определяться. Обновите каталог PPD, создайте принтер и выполните разрешённую тестовую печать PDF. Проверьте очередь и физический результат. Затем отдельно проверьте используемые функции домена, сканирования, доставки и SMB. Установка пакета сама по себе не подтверждает эти подключения.

## Обновление и переход с архива

Остановите приём заданий и службу. Сохраните согласованный комплект базы, spool, сканов, конфигурации и ключей. При PostgreSQL сохраняйте и внешнюю БД. Выполните apt-get install с путём к новому RPM своей ветки/архитектуры. Изменённый environment сохраняется; при изменении шаблона может появиться .rpmnew — сравните его вручную, не перезаписывая токен. Проверьте версию и явно запустите службу. Автоматического перезапуска при обновлении нет.

При переходе с ручной установки старый /etc/systemd/system/goprint.service и /usr/local/bin/goprintd могут перекрывать пакетные файлы. Сохраните их, перенесите параметры и данные, проверьте владельца данных, затем уберите старое переопределение и выполните systemctl daemon-reload. Не запускайте два процесса с одной базой. Не копируйте SQLite во время записи. Откат требует восстановления согласованного комплекта старых бинарников и данных.

Удаление `apt-get remove goprint` останавливает службу, но сохраняет пользователя и данные. Изменённая конфигурация может остаться в .rpmsave. Удаление очередей и ключей выполняйте отдельно только после проверки резервной копии.

## Сборка и проверка пакетов

Исходники упаковки находятся в packaging/altlinux. Сначала создаются статические Linux-архивы через packaging/release.sh, затем `packaging/altlinux/build.sh v0.2.0-beta.5` упаковывает их в официальных контейнерах ALT p10/p11. Для выбора целей используйте GOPRINT_ALT_BRANCHES и GOPRINT_ALT_ARCHS. Go и Docker нужны для сборки, но не для запуска установленного сервера.

Пакеты проверяются установкой с зависимостями, непривилегированным запуском API, преобразованием PDF через тестовый PPD в PostScript, переустановкой, сохранением токена и удалением с сохранением данных. Unit проверяется systemd-analyze verify. Контейнерные проверки не запускают systemd как PID 1: загрузка реальной ОС, политика безопасности и физические МФУ требуют отдельного пилота на целевой машине.
