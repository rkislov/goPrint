# GoPrint

GoPrint — проект сервера печати на Go для Linux и смешанных сетей Windows, macOS и Linux. Проект ориентирован на централизованное управление печатью, доменные учётные записи и интеграцию с Samba.

Текущая версия включает постоянную очередь печати, SQLite/PostgreSQL, файловый spool, HTTP API, CLI и веб-интерфейс с отдельными разделами входа, печати, сканирования и настроек. Отправка документов поддерживается через IPP/IPPS, Socket/JetDirect и SMB3. Добавлены доменный вход AD/Samba AD по LDAPS/StartTLS, роли и входящий IPP для подключения Linux/Windows. Добавлены мониторинг SNMP/IPP и уведомления, личные назначения WebDAV/FTP/FTPS, Kerberos/SPNEGO SSO, личный Follow Me-код, ACL и параметры принтеров, доставка сканов по SMTP, приём от доверенного email-шлюза и ClamAV/ICAP. USB, NTLM-вход в GoPrint и подтверждение физической печати пока не реализованы. Добавлен локальный входящий мост Samba → GoPrint с проверкой Unix UID и доменного UPN.

## Сборка и запуск

Нужен Go 1.26.10 или новее. На Linux и macOS:

```sh
make build
export GOPRINT_TOKEN="$(openssl rand -hex 32)"
./bin/goprintd
```

Консоль: [http://127.0.0.1:8631](http://127.0.0.1:8631). На отдельном экране входа введите `GOPRINT_TOKEN`. Браузер получает сессию на 8 часов в HttpOnly / SameSite=Strict cookie; сам токен в browser storage не сохраняется. По умолчанию сервер слушает loopback. Для сетевого доступа обязательны собственные TLS-сертификат и ключ. Без настройки домена доступен локальный администратор. Доменный вход и разграничение заданий включаются через `-domain-config`; см. дополнение ниже.

Данные по умолчанию находятся в `./var/goprint`. Каталог должен принадлежать пользователю сервера; права каталога устанавливаются в `0700`. Одновременно с одним каталогом может работать только один `goprintd`.

## Печать через CLI

CLI использует `GOPRINT_TOKEN` из окружения. Флаги указываются **перед** командой.

```sh
./bin/goprintctl add-printer Office ipp://192.168.1.50:631/ipp/print
./bin/goprintctl printers
./bin/goprintctl submit PRINTER_ID document.pdf
./bin/goprintctl jobs
./bin/goprintctl job JOB_ID
./bin/goprintctl events JOB_ID
./bin/goprintctl pause PRINTER_ID
./bin/goprintctl resume PRINTER_ID
./bin/goprintctl cancel JOB_ID
```

Для принтера, принимающего готовые RAW-данные:

```sh
./bin/goprintctl -format application/octet-stream add-printer RawPrinter socket://192.168.1.51:9100
./bin/goprintctl -format application/octet-stream submit PRINTER_ID document.prn
```

Формат по умолчанию — `application/pdf`. Без PPD формат должен поддерживаться самим принтером. С выбранным PPD сервер выполняет преобразование автоматически. Для IPPS проверяется сертификат устройства через системное хранилище доверия. Учётные данные в URI не поддерживаются.

## Поведение очереди

- Документ записывается и синхронизируется на диск до подтверждения приёма. Максимальный размер — 100 МиБ, включая загрузки без `Content-Length`.
- Задания одного принтера отправляются последовательно. Число обработчиков настраивается через `-workers` (по умолчанию 4).
- `queued` — ожидает отправки; `processing` — отправляется; `submitted` — передано устройству, физическая печать не подтверждена.
- `failed` — доставка не состоялась либо IPP-принтер вернул отказ; `unknown` — результат неоднозначен. Перед повторной отправкой проверьте очередь устройства.
- После перезапуска ожидающие задания сохраняются, незавершённые `processing` переходят в `unknown`. Автоматических повторов нет.
- Отмена доступна для `queued`. Пауза запрещает новые отправки на принтер и не прерывает текущую.
- При SIGTERM/SIGINT сервер прекращает брать новые задания и ожидает текущие отправки. Повторный сигнал прерывает ожидание.
- Файлы документов и журнал событий сохраняются без автоматической очистки. Пока нет общей дисковой квоты; контролируйте свободное место. Для согласованной резервной копии остановите сервер и копируйте весь каталог данных.

Владелец задания определяется подтверждённой личностью: `local-admin` или доменный UPN. Пользователи видят собственные задания; администраторы — все. Поле пользователя из запроса не используется как подтверждение личности.

## HTTP API

Для `/api/*` требуется заголовок `Authorization: Bearer TOKEN`.

- `GET /api/printers`, `POST /api/printers` — список и создание принтера (`name`, `uri`, `formats`, опционально `paused`).
- `PUT /api/printers/{id}/paused` — JSON `{"paused": true}` или `false`.
- `POST /api/jobs?printer=ID&title=TITLE` — тело документа и его MIME-тип в `Content-Type`; ответ `201` после сохранения.
- `GET /api/jobs` — последние 200 заданий; `GET /api/jobs/{id}` — одно задание.
- `GET /api/jobs/{id}/events` — журнал состояний.
- `POST /api/jobs/{id}/cancel` — отмена ожидающего задания; `409`, если состояние уже изменилось.

```sh
make check

```

Linux-бинарники для amd64 и arm64 собираются без CGO в `dist/`. Пример unit-файла: [packaging/goprint.service](packaging/goprint.service).

Для systemd установите бинарник в `/usr/local/bin`, создайте системного пользователя `goprint` и файл `/etc/goprint/environment` с правами `0600`, содержащий `GOPRINT_TOKEN=...`. Установите unit-файл и выполните `systemctl enable --now goprint`. Готовые `.deb`/`.rpm` в эту версию не входят.

## PPD и фильтры

При первом запуске каталог OpenPrinting Foomatic и официальный набор PPD Катюша загружаются в фоне. В настройках доступны поиск по модели, фильтр по производителю, выбор PPD при создании принтера и обновление каталога. Встроенного полного набора всех когда-либо выпущенных PPD нет: охват ограничен PPD-файлами официального `OpenPrinting/foomatic-db` и проверенным официальным набором Катюша. Сгенерированные из XML модели и закрытые драйверы производителей в него не входят.

Каталог и исходный архив с лицензиями хранятся в `var/goprint/ppds`, отдельно от исходного кода. Отображается SHA-256 источника. Обновление не требует загрузки PPD на GitHub. Для отключения сетевой предзагрузки используйте `-preload-ppds=false`. Импорт ранее загруженного официального архива:

```sh
./bin/goprint-ppds -archive foomatic-db.tar.gz -dir ./var/goprint/ppds
```

Импорт через CLI выполняйте при остановленном сервере; затем запустите сервер заново. Выбранный PPD применяется автоматически через системный `cupsfilter`: PDF, PostScript и изображения проходят цепочку модели перед отправкой. Watermark наносится до фильтрации. Ошибка или отсутствие фильтра блокирует отправку; исходный файл сохраняется. Сервер должен работать от непривилегированного пользователя. Лимит результата — 512 МиБ (`-filter-output-mib`), время фильтрации — 90 секунд. PPD и драйверы должны происходить из доверенного источника. Личные бумага, дуплекс и цвет задаются в «Мои принтеры» в пределах возможностей PPD.

Раздел «Фильтры» показывает установленные компоненты. На Debian/Ubuntu кнопка подготовки пакетов вызывает `apt-get download` для cups-filters, Ghostscript, Poppler и распространённых пакетов драйверов. Пакеты сохраняются в `var/goprint/filters`; установка и разрешение зависимостей остаются задачей администратора (`apt install /absolute/path/to/filters/*.deb` с нужными привилегиями). Сервер не запускает sudo и не устанавливает пакеты от root. На macOS загрузка Linux-пакетов недоступна; показаны системные фильтры. Для Debian/Ubuntu установите `sudo apt install cups cups-filters ghostscript poppler-utils`; для конкретных моделей могут понадобиться дополнительные пакеты драйверов.

## Сканирование / Scan Anywhere

Поддерживаются два базовых сценария:

- Удалённый запуск на вручную добавленном eSCL / AirScan-устройстве: стекло или автоподатчик, A4, RGB, 150/300/600 dpi, запрос JPEG или PDF. Возможности должны поддерживаться самим устройством. Автообнаружение и WSD пока не реализованы.
- Приём PDF/JPEG/PNG от МФУ по WebDAV, FTP и explicit FTPS через назначения с привязкой к пользователю. У каждого назначения отдельный случайный пароль, показанный один раз; сохраняется его SHA-256. Смена получателя автоматически отзывает старый пароль.

Параметры адресной книги МФУ находятся в разделе «Приём сканов»: WebDAV URL `/inbox/DESTINATION_ID/`, логин и пароль назначения; для FTP/FTPS — управляющий порт, PASV/EPSV и папка `/`. FTP-приёмник по умолчанию выключен. FTPS использует сертификат HTTPS; обычный FTP разрешается явно и требует CIDR-подсетей. Старые WebDAV-адреса сканеров сохраняют совместимость и владельца local-admin. Подробности — в [инструкции МФУ](docs/SCAN-INBOX.md). SMB-приёмник не реализован.

Сетевой запуск с HTTPS:

```sh
./bin/goprintd -listen 0.0.0.0:8631 -tls-cert /path/server.crt -tls-key /path/server.key
```

Используйте сертификат, которому доверяют браузер и МФУ. Пересылка с устройства на loopback-адрес другого компьютера невозможна. Доступны локальный административный вход и доменные личные кабинеты. Пользователь получает только собственные сканы; администратор создаёт личные назначения для МФУ. LDAP должен подтверждать доменного получателя при приёме.

Документы сохраняются в `var/goprint/scans`. Лимит входящего файла и суммарного результата удалённого сканирования — 100 МиБ, удалённое задание ограничено 3 минутами. Одновременно допускается до четырёх сканеров, по одному заданию на устройство. Существующий лимит удалённого задания — 99 страниц. Многостраничные результаты выдаются ZIP-архивом отдельных файлов, а не объединённым PDF. Незавершённые задания после перезапуска отмечаются ошибкой и не запускаются повторно автоматически. Автоочистки входящих документов нет.

## SIEM

В настройках есть отдельная вкладка SIEM. Поддерживается Syslog RFC 5424 с JSON-сообщением и octet-counting framing (RFC 6587) через TCP или TLS. Примеры адресов: `tls://siem.example.org:6514`, `tcp://127.0.0.1:514`. Для TLS используется проверка сертификата системным хранилищем доверия; отключения проверки нет. SIEM-экспорт по умолчанию выключен.

Передаются события состояний заданий: сервер (`instance_id`), `event_id`, задание, пользователь, принтер, время, статус, формат, размер и техническая причина. Названия и содержимое документов не передаются. Журнал в SQLite или PostgreSQL используется как постоянная очередь экспорта; позиция сохраняется после успешной записи в TCP/TLS-соединение. При сбое до сохранения позиции возможен повтор — дедупликация выполняется по `instance_id` + `event_id`. Syslog не даёт подтверждения индексации события со стороны SIEM. Это не механизм гарантированного SIEM-подтверждения или защищённого от изменения аудита. Позиция общая для настроенного приёмника, смена адреса не запускает полный исторический экспорт заново.

## Watermark

Отдельный пункт меню Watermark управляет общей политикой маркировки PDF. Настраиваются текст, непрозрачность, угол и размер шрифта. Подстановки: `{{user}}`, `{{job}}`, `{{date}}` (UTC). Используется Roboto с кириллицей. Политика по умолчанию выключена и применяется в момент отправки задания на всех принтерах.

При включённой политике неподдерживаемые форматы отклоняются, а ошибка маркировки блокирует отправку. Подготовка PDF выполняется в отдельном процессе с контекстным сроком задания и мягким лимитом памяти Go 512 МиБ; токен администратора дочернему процессу не передаётся. Исходный spool-файл сохраняется неизменным. Версия применённой политики записывается в журнал событий и может передаваться в SIEM.

Watermark относится только к печати PDF, не к сканированиям и RAW/PS. Маркировка изменяет PDF и может нарушить существующие цифровые подписи. Это не DRM и не механизм запрета копирования документа. Логотипы, отдельные политики по группам и по принтерам, а также классификация документов пока не реализованы.

## Домен, Катюша и клиентские компьютеры

[Настройка AD/Samba AD, PPD Катюша и автонастройка Linux/Windows](docs/DOMAIN-AND-CLIENTS.md) описывает базовые функции домена и PPD. Поддерживается вход по LDAPS/обязательному StartTLS с разрешённой группой и отдельной группой администраторов. Пример без секретов: [domain.example.json](packaging/domain.example.json).

В «Подключение» доступны сценарии CUPS с виртуальным PDF-PPD и Microsoft IPP Class Driver. Печать проходит входящий IPP GoPrint и серверные политики. Настройка Windows требует проверки HTTP Basic в конкретной версии/политике; Kerberos SSO настраивается отдельно через realm/SPN и keytab. Чтение описания известного IPP-принтера разрешено для установки, отправка и управление заданиями защищены авторизацией.

Официальный ZIP Катюша загружается в каталог данных и проверяется по закреплённому SHA-256; импортировано 35 PPD. Пакетные установщики автоматически не запускаются. Нативные фильтры из этого пакета доступны только для Linux amd64; на GitHub они не включаются.

Для крупных установок доступен PostgreSQL с отдельным приватным DSN-файлом. Команда `goprint-migrate` переносит метаданные из SQLite с пробным запуском, транзакцией и сверкой контрольных сумм. Подключение, резервное копирование и откат описаны в [инструкции PostgreSQL](docs/POSTGRESQL.md).

Готовые Linux-сборки и PDF-инструкции: [v0.2.0-beta.3](https://github.com/rkislov/goPrint/releases/tag/v0.2.0-beta.3). Инструкции в исходном виде: [администратору](docs/ADMINISTRATOR.md), [пользователю](docs/USER.md).

[Корпоративные функции бета-версии](docs/BETA-OPERATIONS.md): создание и загрузка keytab, ACL, личные параметры печати, Follow Me, SMTP, доверенный email-шлюз, ClamAV/ICAP. Режим PostgreSQL по-прежнему рассчитан на один активный процесс GoPrint и отдельный файловый spool.

Мониторинг аппаратных счётчиков и расходников, предупреждения в интерфейсе и почтовые уведомления: [настройка для администратора](docs/MONITORING.md).

[Приём сканов с МФУ по WebDAV / FTP / FTPS](docs/SCAN-INBOX.md): личные назначения, параметры адресной книги и настройка пассивных портов.

## Мобильная очередь и QR устройств

Адаптивный веб-интерфейс: личная очередь карточками, выпуск Follow Me по QR и запуск личного сканирования eSCL / AirScan с проверкой ACL. Администратор создаёт PNG QR-кода, печатает наклейку и связывает МФУ со сканером. Для наклеек требуется доступный телефону HTTPS `public-url`. Для обычных пользователей запуск сканирования по умолчанию закрыт до настройки привязки и прав. Возможности включены в выпуск v0.2.0-beta.3.

Презентация продукта, 23 слайда: [PowerPoint](docs/presentation/GoPrint-Product.pptx) · [PDF](docs/presentation/GoPrint-Product.pdf).

Проверка двух направлений печати через Samba и ограничения текущей интеграции описаны в [SAMBA.md](docs/SAMBA.md). Исходящая печать SMB3 настраивается через «Подключение SMB» в карточке принтера; требуется установленный smbclient. Для входящей печати используйте новый Unix-мост с goprint-samba-submit; простой мост с токеном администратора не сохраняет владельца исходного задания.
