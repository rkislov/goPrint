# GoPrint

GoPrint — проект сервера печати на Go для Linux и смешанных сетей Windows, macOS и Linux. Проект ориентирован на централизованное управление печатью, доменные учётные записи и интеграцию с Samba.

Текущая версия включает постоянную очередь печати, SQLite, файловый spool, HTTP API, CLI и веб-интерфейс с отдельными разделами входа, печати, сканирования и настроек. Отправка документов поддерживается через IPP/IPPS и Socket/JetDirect. Доменная авторизация, входящий IPP, Samba, USB, запуск цепочек PPD-фильтров и подтверждение физической печати пока не реализованы.

## Сборка и запуск

Нужен Go 1.25 или новее. На Linux и macOS:

```sh
make build
export GOPRINT_TOKEN="$(openssl rand -hex 32)"
./bin/goprintd
```

Консоль: [http://127.0.0.1:8631](http://127.0.0.1:8631). На отдельном экране входа введите `GOPRINT_TOKEN`. Браузер получает сессию на 8 часов в HttpOnly / SameSite=Strict cookie; сам токен в browser storage не сохраняется. По умолчанию сервер слушает loopback. Для сетевого доступа обязательны собственные TLS-сертификат и ключ. Доменного разграничения пользователей пока нет.

Данные по умолчанию находятся в `./var/goprint`. Каталог должен принадлежать пользователю сервера; права каталога устанавливаются в `0700`. Одновременно с одним каталогом может работать только один `goprintd`.

## Печать через CLI

CLI использует `GOPRINT_TOKEN` из окружения. Флаги указываются **перед** командой.

```sh
./bin/goprintctl add-printer Office ipp://192.168.1.50:631/ipp/print
./bin/goprintctl printers
./bin/goprintctl submit PRINTER_ID document.pdf
./bin/goprintctl jobs
./bin/goprintctl job JOB_ID
./bin/goprintctl events JOB_ID
./bin/goprintctl pause PRINTER_ID
./bin/goprintctl resume PRINTER_ID
./bin/goprintctl cancel JOB_ID
```

Для принтера, принимающего готовые RAW-данные:

```sh
./bin/goprintctl -format application/octet-stream add-printer RawPrinter socket://192.168.1.51:9100
./bin/goprintctl -format application/octet-stream submit PRINTER_ID document.prn
```

Формат по умолчанию — `application/pdf`. Он должен поддерживаться самим принтером: сервер не преобразует документы. Для IPPS проверяется сертификат устройства через системное хранилище доверия. Учётные данные в URI не поддерживаются.

## Поведение очереди

- Документ записывается и синхронизируется на диск до подтверждения приёма. Максимальный размер — 100 МиБ, включая загрузки без `Content-Length`.
- Задания одного принтера отправляются последовательно. Число обработчиков настраивается через `-workers` (по умолчанию 4).
- `queued` — ожидает отправки; `processing` — отправляется; `submitted` — передано устройству, физическая печать не подтверждена.
- `failed` — доставка не состоялась либо IPP-принтер вернул отказ; `unknown` — результат неоднозначен. Перед повторной отправкой проверьте очередь устройства.
- После перезапуска ожидающие задания сохраняются, незавершённые `processing` переходят в `unknown`. Автоматических повторов нет.
- Отмена доступна для `queued`. Пауза запрещает новые отправки на принтер и не прерывает текущую.
- При SIGTERM/SIGINT сервер прекращает брать новые задания и ожидает текущие отправки. Повторный сигнал прерывает ожидание.
- Файлы документов и журнал событий сохраняются без автоматической очистки. Пока нет общей дисковой квоты; контролируйте свободное место. Для согласованной резервной копии остановите сервер и копируйте весь каталог данных.

Все задания принадлежат `local-admin`. Поле пользователя из запроса не используется как подтверждение личности.

## HTTP API

Для `/api/*` требуется заголовок `Authorization: Bearer TOKEN`.

- `GET /api/printers`, `POST /api/printers` — список и создание принтера (`name`, `uri`, `formats`, опционально `paused`).
- `PUT /api/printers/{id}/paused` — JSON `{"paused": true}` или `false`.
- `POST /api/jobs?printer=ID&title=TITLE` — тело документа и его MIME-тип в `Content-Type`; ответ `201` после сохранения.
- `GET /api/jobs` — последние 200 заданий; `GET /api/jobs/{id}` — одно задание.
- `GET /api/jobs/{id}/events` — журнал состояний.
- `POST /api/jobs/{id}/cancel` — отмена ожидающего задания; `409`, если состояние уже изменилось.

## Проверки и Linux

```sh
make check
make linux
```

Linux-бинарники для amd64 и arm64 собираются без CGO в `dist/`. Пример unit-файла: [packaging/goprint.service](packaging/goprint.service).

Для systemd установите бинарник в `/usr/local/bin`, создайте системного пользователя `goprint` и файл `/etc/goprint/environment` с правами `0600`, содержащий `GOPRINT_TOKEN=...`. Установите unit-файл и выполните `systemctl enable --now goprint`. Готовые `.deb`/`.rpm` в эту версию не входят.

## PPD и фильтры

При первом запуске каталог OpenPrinting Foomatic загружается в фоне. В настройках доступны поиск по модели, фильтр по производителю, выбор PPD при создании принтера и обновление каталога. Встроенного полного набора всех когда-либо выпущенных PPD нет: охват ограничен PPD-файлами официального `OpenPrinting/foomatic-db`, доступными в загруженном архиве. Сгенерированные из XML модели и закрытые драйверы производителей в него не входят.

Каталог и исходный архив с лицензиями хранятся в `var/goprint/ppds`, отдельно от исходного кода. Отображается SHA-256 источника. Обновление не требует загрузки PPD на GitHub. Для отключения сетевой предзагрузки используйте `-preload-ppds=false`. Импорт ранее загруженного официального архива:

```sh
./bin/goprint-ppds -archive foomatic-db.tar.gz -dir ./var/goprint/ppds
```

Импорт через CLI выполняйте при остановленном сервере; затем запустите сервер заново. Привязка PPD сохраняется, но его директивы и команды не исполняются. Наличие PPD не означает готовность драйвера: документ должен быть в формате, который понимает устройство.

Раздел «Фильтры» показывает установленные компоненты. На Debian/Ubuntu кнопка подготовки пакетов вызывает `apt-get download` для cups-filters, Ghostscript, Poppler и распространённых пакетов драйверов. Пакеты сохраняются в `var/goprint/filters`; установка и разрешение зависимостей остаются задачей администратора (`apt install /absolute/path/to/filters/*.deb` с нужными привилегиями). Сервер не запускает sudo и не устанавливает пакеты от root. На macOS загрузка Linux-пакетов недоступна; показаны системные фильтры. Автоматическое выполнение цепочек фильтров не реализовано.

## Сканирование / Scan Anywhere

Поддерживаются два базовых сценария:

- Удалённый запуск на вручную добавленном eSCL / AirScan-устройстве: стекло или автоподатчик, A4, RGB, 150/300/600 dpi, запрос JPEG или PDF. Возможности должны поддерживаться самим устройством. Автообнаружение и WSD пока не реализованы.
- Приём PDF/JPEG/PNG от МФУ через WebDAV в общий входящий раздел локального администратора. При добавлении устройства выдаётся отдельный случайный пароль, который показывается один раз; в базе хранится только его SHA-256. Пароль устройства не даёт доступа к административному API и скачиванию документов.

Для WebDAV укажите адрес `https://SERVER:PORT/inbox/SCANNER_ID/`, имя пользователя `SCANNER_ID` и выданный пароль. Поддерживаются OPTIONS, PROPFIND, MKCOL и PUT; это приёмник файлов, а не универсальный WebDAV-диск. Совместимость зависит от реализации WebDAV в прошивке МФУ. SMB/FTP/email-приёмники не реализованы.

Сетевой запуск с HTTPS:

```sh
./bin/goprintd -listen 0.0.0.0:8631 -tls-cert /path/server.crt -tls-key /path/server.key
```

Используйте сертификат, которому доверяют браузер и МФУ. Пересылка с устройства на loopback-адрес другого компьютера невозможна. Сетевой доступ даёт вход по токену локального администратора; доменные личные кабинеты и назначение документов доменным пользователям пока отсутствуют.

Документы сохраняются в `var/goprint/scans`. Лимит входящего файла и суммарного результата удалённого сканирования — 100 МиБ, удалённое задание ограничено 3 минутами. Одновременно допускается до четырёх сканеров, по одному заданию на устройство. Существующий лимит удалённого задания — 99 страниц. Многостраничные результаты выдаются ZIP-архивом отдельных файлов, а не объединённым PDF. Незавершённые задания после перезапуска отмечаются ошибкой и не запускаются повторно автоматически. Автоочистки входящих документов нет.

## SIEM

В настройках есть отдельная вкладка SIEM. Поддерживается Syslog RFC 5424 с JSON-сообщением и octet-counting framing (RFC 6587) через TCP или TLS. Примеры адресов: `tls://siem.example.org:6514`, `tcp://127.0.0.1:514`. Для TLS используется проверка сертификата системным хранилищем доверия; отключения проверки нет. SIEM-экспорт по умолчанию выключен.

Передаются события состояний заданий: сервер (`instance_id`), `event_id`, задание, пользователь, принтер, время, статус, формат, размер и техническая причина. Названия и содержимое документов не передаются. Локальный журнал SQLite используется как постоянная очередь экспорта; позиция сохраняется после успешной записи в TCP/TLS-соединение. При сбое до сохранения позиции возможен повтор — дедупликация выполняется по `instance_id` + `event_id`. Syslog не даёт подтверждения индексации события со стороны SIEM. Это не механизм гарантированного SIEM-подтверждения или защищённого от изменения аудита. Позиция общая для настроенного приёмника, смена адреса не запускает полный исторический экспорт заново.

## Watermark

Отдельный пункт меню Watermark управляет общей политикой маркировки PDF. Настраиваются текст, непрозрачность, угол и размер шрифта. Подстановки: `{{user}}`, `{{job}}`, `{{date}}` (UTC). Используется Roboto с кириллицей. Политика по умолчанию выключена и применяется в момент отправки задания на всех принтерах.

При включённой политике неподдерживаемые форматы отклоняются, а ошибка маркировки блокирует отправку. Подготовка PDF выполняется в отдельном процессе с контекстным сроком задания и мягким лимитом памяти Go 512 МиБ; токен администратора дочернему процессу не передаётся. Исходный spool-файл сохраняется неизменным. Версия применённой политики записывается в журнал событий и может передаваться в SIEM.

Watermark относится только к печати PDF, не к сканированиям и RAW/PS. Маркировка изменяет PDF и может нарушить существующие цифровые подписи. Это не DRM и не механизм запрета копирования документа. Логотипы, отдельные политики по группам и по принтерам, а также классификация документов пока не реализованы.
