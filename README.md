# GoPrint

GoPrint — проект сервера печати на Go для Linux и смешанных сетей Windows, macOS и Linux. Проект ориентирован на централизованное управление печатью, доменные учётные записи и интеграцию с Samba.

Текущая версия — локальная очередь печати: SQLite, файловый spool, HTTP API, CLI и простая веб-консоль. Отправка документов поддерживается через IPP/IPPS и Socket/JetDirect. Доменная авторизация, входящий IPP, Samba, USB, преобразование документов и подтверждение физической печати пока не реализованы.

## Сборка и запуск

Нужен Go 1.25 или новее. На Linux и macOS:

```sh
make build
export GOPRINT_TOKEN="$(openssl rand -hex 32)"
./bin/goprintd
```

Консоль: [http://127.0.0.1:8631](http://127.0.0.1:8631). Введите тот же `GOPRINT_TOKEN`; он используется как токен локального администратора. Сервер принимает подключения только на loopback. Не публикуйте API через прокси в сеть: доменных пользователей и разграничения доступа в этой версии нет.

Данные по умолчанию находятся в `./var/goprint`. Каталог должен принадлежать пользователю сервера; права каталога устанавливаются в `0700`. Одновременно с одним каталогом может работать только один `goprintd`.

## Печать через CLI

CLI использует `GOPRINT_TOKEN` из окружения. Флаги указываются **перед** командой.

```sh
./bin/goprintctl add-printer Office ipp://192.168.1.50:631/ipp/print
./bin/goprintctl printers
./bin/goprintctl submit PRINTER_ID document.pdf
./bin/goprintctl jobs
./bin/goprintctl job JOB_ID
./bin/goprintctl events JOB_ID
./bin/goprintctl pause PRINTER_ID
./bin/goprintctl resume PRINTER_ID
./bin/goprintctl cancel JOB_ID
```

Для принтера, принимающего готовые RAW-данные:

```sh
./bin/goprintctl -format application/octet-stream add-printer RawPrinter socket://192.168.1.51:9100
./bin/goprintctl -format application/octet-stream submit PRINTER_ID document.prn
```

Формат по умолчанию — `application/pdf`. Он должен поддерживаться самим принтером: сервер не преобразует документы. Для IPPS проверяется сертификат устройства через системное хранилище доверия. Учётные данные в URI не поддерживаются.

## Поведение очереди

- Документ записывается и синхронизируется на диск до подтверждения приёма. Максимальный размер — 100 МиБ, включая загрузки без `Content-Length`.
- Задания одного принтера отправляются последовательно. Число обработчиков настраивается через `-workers` (по умолчанию 4).
- `queued` — ожидает отправки; `processing` — отправляется; `submitted` — передано устройству, физическая печать не подтверждена.
- `failed` — доставка не состоялась либо IPP-принтер вернул отказ; `unknown` — результат неоднозначен. Перед повторной отправкой проверьте очередь устройства.
- После перезапуска ожидающие задания сохраняются, незавершённые `processing` переходят в `unknown`. Автоматических повторов нет.
- Отмена доступна для `queued`. Пауза запрещает новые отправки на принтер и не прерывает текущую.
- При SIGTERM/SIGINT сервер прекращает брать новые задания и ожидает текущие отправки. Повторный сигнал прерывает ожидание.
- Файлы документов и журнал событий сохраняются без автоматической очистки. Пока нет общей дисковой квоты; контролируйте свободное место. Для согласованной резервной копии остановите сервер и копируйте весь каталог данных.

Все задания принадлежат `local-admin`. Поле пользователя из запроса не используется как подтверждение личности.

## HTTP API

Для `/api/*` требуется заголовок `Authorization: Bearer TOKEN`.

- `GET /api/printers`, `POST /api/printers` — список и создание принтера (`name`, `uri`, `formats`, опционально `paused`).
- `PUT /api/printers/{id}/paused` — JSON `{"paused": true}` или `false`.
- `POST /api/jobs?printer=ID&title=TITLE` — тело документа и его MIME-тип в `Content-Type`; ответ `201` после сохранения.
- `GET /api/jobs` — последние 200 заданий; `GET /api/jobs/{id}` — одно задание.
- `GET /api/jobs/{id}/events` — журнал состояний.
- `POST /api/jobs/{id}/cancel` — отмена ожидающего задания; `409`, если состояние уже изменилось.

## Проверки и Linux

```sh
make check
make linux
```

Linux-бинарники для amd64 и arm64 собираются без CGO в `dist/`. Пример unit-файла: [packaging/goprint.service](packaging/goprint.service).

Для systemd установите бинарник в `/usr/local/bin`, создайте системного пользователя `goprint` и файл `/etc/goprint/environment` с правами `0600`, содержащий `GOPRINT_TOKEN=...`. Установите unit-файл и выполните `systemctl enable --now goprint`. Готовые `.deb`/`.rpm` в эту версию не входят.
